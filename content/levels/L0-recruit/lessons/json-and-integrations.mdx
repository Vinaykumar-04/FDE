## Why it matters for an FDE
Business systems often need to exchange customer, order, or event data. JSON is one common format you’ll inspect while building those connections.

## The idea
JSON is like a labeled form. Each key names a field, and its value holds the information. For example, `{ "status": "ready" }` says that the status field has the text value “ready”.

## Worked example
An order service might send `{ "orderId": 42, "status": "packed" }`. An integration reads those fields and passes the information to another system. Names, data types, and required fields need to match what the receiving system expects.

## Common mistakes
- Missing quotation marks or commas.
- Sending a number as text when the receiving system expects a number.
- Assuming two systems use the same field names.
