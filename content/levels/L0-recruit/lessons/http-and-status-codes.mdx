## Why it matters for an FDE
When an integration fails, HTTP details help you find where the problem happened. They are clues you can share with a customer or engineering team.

## The idea
HTTP is like a request slip sent to a service desk. The client asks for something; the server replies with a result and a status code. A code is a clue, not a complete diagnosis.

## Worked example
A browser asks an API for `/orders/42`. A `200` response usually means the request worked. A `404` suggests that order wasn’t found at that address. A `500` suggests the server had a problem handling the request.

## Common mistakes
- Treating every 4xx or 5xx response as the same issue.
- Assuming a 200 response means the returned data is correct.
- Sharing sensitive request data while reporting an error.
