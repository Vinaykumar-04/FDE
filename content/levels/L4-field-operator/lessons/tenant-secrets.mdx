## Why it matters for an FDE

A multi-customer product must keep each customer’s data and credentials separated.

## The idea

Tenant isolation checks that every request is scoped to the correct customer. Secrets are credentials stored and delivered through a protected mechanism.

> Each customer gets a separate locked room; a secret is a key stored in a controlled key cabinet.

## Worked example

A user requests an export. Derive the tenant from the authenticated session, verify access, and fetch only that tenant’s records.

## Common mistakes

- Trusting a tenant ID supplied by the browser or storing a token in source code.
- Enforce tenant scope on the server side, test cross-tenant access attempts, and rotate exposed credentials.
