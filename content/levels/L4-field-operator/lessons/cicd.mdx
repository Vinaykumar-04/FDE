## Why it matters for an FDE

Customer-facing changes should be checked before they reach a live environment.

## The idea

Continuous integration runs checks on code changes. Continuous delivery prepares a tested change for release through a controlled process.

> It is like inspecting a package at each checkpoint before it leaves the warehouse.

## Worked example

A pull request triggers lint, unit tests, build, and a smoke test. A release then promotes the reviewed artifact to the customer environment.

## Common mistakes

- Treating a green build as proof that every customer workflow works or releasing without a rollback plan.
- Make checks repeatable, review the diff, deploy gradually when possible, and know how to reverse a bad release.
