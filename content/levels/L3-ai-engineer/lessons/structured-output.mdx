## Why it matters for an FDE

Software needs predictable fields to use model responses safely in a workflow.

## The idea

Structured output constrains a model response to a defined shape, often JSON with required fields and allowed values.

> It is like a form with labeled boxes: each answer has a place, and missing information can be marked clearly.

## Worked example

Extract a date, issue type, and confidence from a ticket. Validate the response against a schema before creating a downstream record.

## Common mistakes

- Assuming valid-looking JSON is semantically correct or using an unchecked field to trigger an important action.
- Validate types and allowed values, handle missing or invalid fields, and require confirmation for consequential actions.
