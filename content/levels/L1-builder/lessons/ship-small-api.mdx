## Why it matters for an FDE

A small end-to-end service teaches the handoff between code, configuration, and a running environment.

## The idea

A service should expose a clear interface, validate input, return predictable responses, and provide enough logs to diagnose failures.

> Think of a service like a staffed counter: it needs a clear request form, rules for valid requests, and a receipt showing what happened.

## Worked example

Build a health endpoint and a read-only customer status endpoint. Validate the customer ID, return JSON, and log a request ID for each call.

## Common mistakes

- Returning internal errors to users or deploying before checking the service with realistic inputs.
- Run local checks, test the error path, document configuration, and verify the deployed endpoint from the expected network.
